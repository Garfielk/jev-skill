# September 22 — check evidence again when reusing a judgment

This round expands the [existing pitfalls guide](../../skills/jev/references/pitfalls.md#evidence-freshness)
and both README prompts. It adds no scenario, model adapter or cache implementation.
The five skills, 108 scenarios, 57 project/resource rows and 14 historical I/O pairs
are unchanged. No community software was installed or benchmark reproduced.

## What earned an update

The dbt-assay author's [verification report at 6d568429](https://github.com/ryan-sunny/dbt-assay/blob/6d568429ef69d2092fb7954bf1951faca60c4f16/docs/VERIFICATION.md)
separates a tested question from confirmed findings. Two details add something
concrete to our existing context and uncertainty advice:

- A claim-specific source can be missing even when the input contains plenty of
  other code. Absence from that excerpt is not evidence of contradiction.
- A newly added guard on the call path did not invalidate old saved answers on
  the read path. The author reports fixing the read path as well.

Our adaptation records decision dependencies, checks current guards before using
stored judgments, and marks stale results without destroying their receipts.
The guide includes three offline test ideas for agent-written integration code.
They are not claimed as an implemented or tested feature of our CLI.

The repository was created September 20 UTC; the inspected commit is dated
September 21 at 23:00:52 UTC. These are GitHub timestamps, not proof of when the
reported field experiments ran. We read the README and verification report, not
the whole codebase or private warehouse. All field outcomes remain author reports.
